# Autowriter (free)

`.github/workflows/daily-articles.yml` runs Mon–Sat at 07:17 (São Paulo) and on demand (Actions → Daily articles → Run workflow, optional count).

- Before writing, `scripts/keyword-check.mjs` checks each `todo` keyword for search demand with the Bing Webmaster keyword research API (secret `BING_WEBMASTER_API_KEY`, or `~/.secrets/bing_webmaster_api_key` locally) and Google Autocomplete. Items are marked `demand.level` `ok`, `weak`, or `none`. A `none` item is rewritten to the best on-topic variant that people actually search, or skipped if no variant fits. Todos are then reordered so stronger-demand keywords go first, with product-linked items kept reasonably mixed. This step uses no LLM tokens.
- Writes the next `todo` items from `queue.json` with the free Gemini API first (secret `GEMINI_API_KEY`; optional variable `GEMINI_MODELS` = comma-separated fallback list). If Gemini errors, returns 503, comes back empty, or still fails the quality checks after its retries, the run falls back to Groq (secret `GROQ_API_KEY`; optional variable `GROQ_MODELS`, default `openai/gpt-oss-120b,openai/gpt-oss-20b,qwen/qwen3.8-27b`). Groq drafts go through the same quality checks. On-demand runs can set `force_provider` to `groq` or `gemini`. The run log, PR summary, and article front matter record which provider and model wrote each piece. Zero-demand items that could not be rewritten are skipped.
- How many per day: repository variable `ARTICLES_PER_DAY` (default 2).
- Checks: word count, H2/H3, a "## Pros and cons" section that leads with **Pros** and uses **Good to know** or **Best results when** (not a drawback-style Cons list), a "## Who it's ideal for" section (no "who should skip it" block), 3–6 in-sentence internal links, no forbidden hosts, no invented test/rating/testimonial/medical claims, no “we have not tested” disclaimers, in-text affiliate CTAs on product articles, benefits-only copy in the product sales section, every source URL must return HTTP 200. A short commission note is inserted by the article layout before the first offer link; the site footer disclosure stays as it is.
- Images: hero + one mid-article photo + 7 Web Story cards (720×960 WebP). The mid-article photo is placed in the section it illustrates. If the article has a product, it uses a seller/producer image from `products.js` and links it to the affiliate URL; otherwise it uses a free stock photo from Pixabay (when secret `PIXABAY_API_KEY` is set; downloaded into the repo, never hotlinked), then Openverse or Wikimedia Commons (CC0 / public domain) as backup. The product card uses the seller photo from `products.js`. Every article hero must be unique: `scripts/autowriter/hero-registry.json` records used heroes by source URL/ID, SHA-256, and a perceptual dHash. New heroes skip any already used photo; mid-article photos also skip images that match a hero.
- Adds up to 3 links from older articles to the new one (exact existing phrase only).
- Runs the Eleventy build + `scripts/check-site.js`; one retry with the error; otherwise skips.
- Opens a PR labeled `autowriter`. **Never auto-merges** — review, edit, merge.

New product: add it to `src/_data/products.js` with João's own affiliate link, a producer image (optional `storyImages: [...]`), and benefits-only `summary` and `points` (no cons or trade-offs; that copy appears in the product box), then add or flip its queue item to `todo`.
